# 桌面学习回顾

B1 工作区保留看课、Tutor、显式练习、作答及反馈的原有关系，并提供以下读取入口：

- **练习结果**：解释与练习中的“练习结果”按当前 Run 的每道题展示持久化作答版本、对应反馈、核对记录和最近反馈执行状态。未保存草稿不计入结果。可返回本题、答案版本、对应反馈及来源；学习记录可切换其他 Session/Run。没有自动评分或掌握率。
- **历史问答**：Tutor 打开或刷新时读取本课程本人已保存问答，选择记录可查看旧回答并继续明确提问。未提交问题不跨刷新恢复。历史问答的原学习范围未持久化，不将当前范围倒填为历史范围。
- **学习资料**：桌面主导航直接进入已保存摘要、重点、术语和章节。旧资料没有 Evidence 关联时只显示文本；章节时间入口是普通定位，不标记为可信引用。章节生成仍需明确操作。

## 读取契约

`GET /api/tasks/{taskId}/qa/history?limit=20&before={recordId}` 返回 `items` 和 `nextCursor`。数量范围1–50，按ID倒序；客户端每轮最多载入最近100条，可刷新回最新。每次按当前用户及未删除课程核验，记录查询同时限定用户/课程，读后再次核验权限与revision。只返回问题、回答、状态、时间及当前有效的来源，排除模型路由、usage、调用记录和执行快照。失败问答不返回原始错误。

来源仅从已经存在的当前 `course_evidence` 校验，历史读取不生成快照、索引、Run或模型调用。旧revision、缺失或不可检索来源不作为可信引用；点击时仍经过工作区原有版本围栏。与任何网络读取相同，响应到达后权限变化由下一次读取/来源操作重新校验。

Study `READ` 增加 `practice_results`，在现有用户/课程/revision/Session/Run 授权内逐题读取最新attempt、优先对应其版本的已完成反馈（否则保留旧反馈）、最近反馈执行状态及该反馈的最新核对记录。它不依赖最近20条反馈窗口推断“无反馈”，不揭示参考答案，不写学习状态。PostgreSQL仍为权威，未新增数据表或执行引擎。

## 验证

前端：`npm ci && npm run test:unit && npm run build && npm audit --audit-level=high`。
后端：`./mvnw test`，MySQL机制测试需独立测试数据库。
Python：`uv run ruff check src tests && uv run ruff format --check src tests && uv run pytest -q`，`AGENT_TEST_DATABASE_URL`必须指向独立PostgreSQL测试库；跳过数据库不算完整通过。

浏览器以1440×900、1280×800验收真实Vue→Java→Python→独立MySQL/PostgreSQL，使用合成材料、Mock模型和离线embedding。它证明交互及持久化机制，不证明真实模型教学质量。移动端保留现有响应式，不在本轮专项验收范围。详细候选身份、原始日志、截图和访问方法随PR交付，不能以HTTP夹具代替真实服务结果。

付费验收的源码身份清单原先冻结56个模块。本轮仅变更其中的 `study/store.py` 读取投影，并把新的 `study/results.py` 加入同一哈希围栏，共57个；旧702b2f8清单原样保存为测试fixture，并断言其余55个原模块哈希不变。身份漂移拒绝测试继续执行。此项是读取候选的代码身份更新，不是模型质量验收，也不授权付费执行；旧冻结评测资产和结果未改写。
