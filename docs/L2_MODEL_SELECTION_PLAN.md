## 开发任务与评分

建议建立独立开发集文件，复用已公开分析的 Study v2 六题：解释、对比、输入应用、错误观念纠正和两道课程外拒答。保留原题来源 ID，并明确标为 development；不修改历史 cases.json 或历史 holdout 标签。评分要点不输入运行模型。新保留集由后续任务独立冻结，本轮不接触。

六题只是配置筛选诊断。沿用既有 90% 门槛时，结构与 90 秒内正确类型需至少 6/6，课程内完整语义需 4/4，课程外正确停止需 2/2，且无严重无据断言；来源校验亦须通过。即使全部通过，仍设 `full_l2_gate_assessed=false`，不代表正式 L2.2 过关。

逐题报告关联原始产物、引用正文、模型配置身份和复核记录，分别记录：

- 解释/答案正确与完整、引用支持、题型区别、三者交集，以及课程外正确拒答。
- 复核误接受/误拒绝：独立检查草稿与证据，再与运行时判断比较；缺少可评分草稿或未完成复核记为不可判定，不强行归类。
- 修订：记录拒绝后是否产生新的候选、是否运行成功、最终语义是否达标。Run 成功不等于修订内容成功。
- 数据库 `finished_at - created_at` 全结果延迟与 nearest-rank P50/P95，包含失败、超时；另存执行时间。
- 实际输入/输出 token，按用途分项；报告缺失 usage 的调用数，不将未知记为零，不与保守预留混算。

独立 AI 评分须标明不是人工金标准，运行时复核不能充当评分者。全部失败保留，不用重跑覆盖。无合格候选时明确“不进入”；通过上述开发筛选且没有未解释的复核风险，才建议“进入新保留集验收”。
