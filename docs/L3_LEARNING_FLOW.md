## 开发顺序与结果

1. CI PostgreSQL 服务、健康检查和测试连接串统一为 `lecturelens_agent_test`，避免数据库安全检查拒绝 CI。
2. 学习助手成为课程默认工作区；读取准备状态，区分未启用、准备中与连接失败。恢复学习目标、已完成产物、最近 20 个 Session 和各自最近 20 次学习任务。
3. 作答由 Python/PostgreSQL 保存，绑定 owner/course/revision/session/run/artifact/question。不可变修改记录、幂等重试、乐观版本冲突和历史分页已实现；刷新恢复真实文字，参考答案仍需主动展开，空白作答不入库。
4. 证据反馈作为独立 Run，读取精确保存版本，模型选择读取课程证据、补充窗口、提交反馈或拒答工具；独立复核意见进入下一次决策，最多两份候选。成功反馈独立存储；用户核对或更正意见另存不可变版本，不覆盖作答或模型原文。

反馈沿用持久调用/工具/token预算、90秒截止、取消、执行锁、课程版本栅栏和 checkpoint。工具记录与反馈写入同一事务，提交后进程中断可重放而不重复发布；失败、课程删除/变更或取消后的迟到结果不得公开。新作答不把旧反馈重新标为新版本。模型只选择授权 Evidence ID，由程序填入原文，学生引文仍须与真实答案精确匹配。

Python 拥有全部学习状态和任务决策；Java 仅转发经认证的命令并前后检查课程权属和版本，MySQL 不保存 Agent 派生作答。该能力不产生分数、掌握程度、长期记忆或自动复习计划。

## 当前边界与下一步

候选 P 增加逐条结构化复核、每条引用的完整已观察上下文、逐段回看、受限修改/保留动作及独立拒答覆盖检查。工具随执行阶段收紧，最新复核意见与剩余预算单独提供，避免反复读相同证据耗尽额度。首次读证据时，模型只看题干与课程形成独立解释，未接触学生作答或反馈草稿；解释是可核查的私有观察，不是答案权威。正常路径4次模型调用，一次修订可在6次内完成。

P开发6/6、已消费旧题回归8/8和冻结后全新保留作答8/8均通过。新保留仍出现1次不必要的复核拒绝，最终6次调用内得到正确结果；这说明复核器仍可能误判。用户已追加无总调用次数上限授权，每 Run 预算仍保持。反馈由 Python `STUDY_FEEDBACK_ENABLED=false` 控制，不因机制测试通过而开放。
