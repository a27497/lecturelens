## 1. 核心交付

主产品链路是：**学习目标 → 读取课程证据 → 模型选择工具并观察结果 → 解释与练习产物 → 用户作答与反馈 → 可更正的复习记忆**。

前四步已有最小实现；隔离冻结BC通过本轮有限课程范围的L2.2门槛，线上C仍未达标；工作区新增未发布的作答持久化、修改历史及独立证据反馈，反馈默认关闭并单独验收；长期记忆未交付。上传、媒体处理、存储和鉴权为这条链路提供基础能力。

## 3. 判断是否在推进 Agent 的验收问题

每个学习能力变更，应能回答：

1. 用户交给 Agent 的目标是什么？最终得到什么可保存、可检查的产物？
2. 哪一步由模型选择？哪些证据、工具失败或用户信息会改变下一步？
3. 工具获得什么最小权限？如何处理错误、无证据、版本变化和预算耗尽？
4. Run 如何追踪、取消和恢复？重复请求或晚到结果如何处理？
5. 与现有路径相比，任务正确性、引用支持、拒答、延迟和调用成本有何变化？

这些问题应由代码路径、执行事件、测试与真实评测回答。语言占比、框架名称、工具数量和后端测试总数仅描述实现，不能代替任务效果证据。

## 4. 后续顺序

| 优先级 | 主线 | 完成依据 |
| --- | --- | --- |
| P0 | L2 内容质量：解释/答案一致、逐题引用支持、不同题型、课程外正确停止 | 新的保留任务达到既定门槛；保留全部失败和资源配置 |
| P1 | Agent 工作区成为学习主入口 | 以目标、执行状态和学习产物组织流程；课程准备、阅读和下载作为配套入口；服务未启用/资料未就绪时可理解、可恢复 |
| P2 | L3.1 实际作答与证据反馈 | 先保存真实答案，再保存独立反馈；模型反馈可核对更正，空答案不形成薄弱点 |
| P3 | Context 与可更正学习记忆 | 多轮引用有效、记忆有来源、可删除，能够改变后续练习与复习安排 |
| P4 | 有实际消费方的工具/Skill 互通 | 外部调用同样受权属与预算控制，有端到端效果证据 |

Java 的新增工作围绕这些能力所需的课程、Evidence、权限或可靠性问题展开。保留已有业务基础设施，避免引入重复执行状态或第二套学习决策逻辑。
