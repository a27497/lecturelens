# 模型使用记录

课程页「模型使用记录」按当前登录 owner 和课程读取白名单投影，打开或刷新不访问模型供应商。Java/MySQL 的系统配置、版本和执行快照仍由原系统管理；Python/PostgreSQL 的个人连接、decision/review 用途与 Run 快照仍由原系统管理。

## 记录语义

| 记录 | 来源与含义 |
| --- | --- |
| 当前下次配置 | 当前系统版本的有效路由，仅展示功能、来源和型号；不代表历史执行或已经调用 |
| 课程处理选择 | 已保存的 PIPELINE 快照、配置版本、来源和冻结时间；ADOPTED 只表示接管时冻结 |
| 普通 QA | `course_qa_record.execution_snapshot_id` 精确关联本次 COURSE_QA 快照；同时保存调用阶段与逻辑调用记录 ID |
| Agent decision/review | 该 Run 的 `model_config` 脱敏投影，分别显示个人连接/服务器默认、型号与连接版本；不读取当前连接替代历史 |
| 调用事件/台账 | 本地开始、返回、失败和重放的记录；本地开始不证明供应商接收，重放不代表新调用，缺少 usage 为未知 |

QA 的 `SKIPPED_NO_EVIDENCE` 表示未调用；`NOT_STARTED` 表示尚未交给适配器；`DISPATCHED` 表示已交给适配器但没有返回响应的记录，可能在出网前失败；`RESPONSE_RECEIVED` 表示适配器返回了响应，不保证解析、引用或教学质量通过。Mock 响应不代表真实模型调用。结果状态与调用阶段分别保存。引用在原 `GenerationFence` 事务中随 QA 一起写入，不按同课程、时间或最新配置猜测关联。

课程调用台账最多显示最近 100 条逻辑调用，QA 最多显示最近 50 条，处理快照最多 50 条。现有处理台账没有逐次快照关联和完整物理重试信息，界面不据此认证某一冻结选择实际被调用；没有记录的跳过原因仍为未知。旧 QA/任务/Run 缺少快照时显示未记录。旧 Run 的环境兼容路径不能追认为创建时冻结。

## 四种证据

| 等级 | 可证明的范围 | 本轮展示 |
| --- | --- | --- |
| 模型发现 | 某连接版本在某时刻的目录可见性 | 发现结果未随执行保存，显示未验证 |
| 单轮协议 | 一次有界请求返回约定工具结果 | 新 Run 冻结该连接版本已有的单次检查结果，显示型号、版本、时间和来源；不执行新探针 |
| 多轮工具兼容 | 工具结果回填后继续决策的协议行为 | 未验证；不把单轮成功或确定性测试升级为云供应商兼容认证 |
| 真实课程质量 | 冻结代码/配置/提示/工具/检索/预算与指定数据集的独立评估 | 未验证；仓库历史候选的有限质量结论不套用到任意当前配置 |

个人连接编辑会清除其当前检查结果。新 Run 只冻结版本匹配的已有单轮结果；旧 Run 的检查观察保持不变。未记录检查的旧 Run 不从当前连接补齐。Java 管理探针没有持久历史可供本视图认证，显示未验证。发现、单轮、兼容性和课程质量均不会自动触发供应商请求；本轮没有付费调用授权。

## 权限与竞态

`GET /api/tasks/{taskId}/model-usage` 从当前认证身份取 owner，在事务内锁定未删除课程的权属，并按 task/owner 限定快照、QA 与调用记录。QA 关联同时检查快照的 task、owner 与 COURSE_QA 类型，伪造其他 owner 的引用不会返回其内容。接口不接收用于授权的 owner 或 snapshot ID。DTO 不包含 catalog、供应商地址、凭据引用、keyLast4、密文或配置 JSON。系统管理未启用时，不查询配置或快照表。

前端只在显式打开/刷新时请求；课程切换、组件销毁和新请求会取消旧请求并递增响应代次，校验返回课程身份。请求开始或权限失败时清空旧卡；Trace 刷新失败也隐藏旧模型投影。账号会话变更继续使用既有文档级认证边界。未改 Evidence 权限、scoped 路由、签名协议、Run 预算、绑定或恢复/取消围栏。

## MySQL 迁移与回滚

`R__course_qa_model_usage.sql` 只增加 QA 的三个可空字段，不回填历史。采用幂等的 repeatable additive migration 是为保留 main 的 V25 水位：待整合 PR #35 已占用 V26–V31，直接先发 V32 会使其后续迁移低于水位。脚本检查字段后执行单条原子 ALTER；崩溃后可安全重跑。不能修改历史 V1–V25、复用 V26–V31、开启 outOfOrder 或 repair 迁移历史。

MySQL 集成测试覆盖旧 QA 的 NULL、实际 MyBatis 新关联写读、A→B 后历史仍为 A，以及 PR3→#35、#35→PR3 两种升级顺序和重复 migrate 无操作。#35 迁移夹具固定为 `146cc883f045d89a87cfe9b083376c8dac204964` 的六个原始 SQL，仅放在测试资源中，生产 Flyway 不扫描；该验证不等于 #35 运行能力验收。未来 #35 迁移变化必须重新验证。

发布前必须先应用此增量迁移，即使系统模型管理关闭也一样；新增 QA 写入需要这些字段。保持该 repeatable 文件名称与已发布内容稳定，后续 schema 变更另增迁移。回滚到本 PR 基线代码时保留新增可空字段、快照、Run 和调用历史，不执行 DROP、清空或反向 DDL；基线会忽略新增字段。回滚代码时仍须保留 Flyway 对该 repeatable 历史的解析：保留原样迁移文件；使用不含该文件的基线 JAR 时，将原文件作为独立 rollback migration bundle 加入 Flyway locations，并先 validate。隔离 MySQL 已验证「基线 V1–V25 + 原样外部 R 文件」验证通过且 migrate 无操作；不要 repair/删除 schema history。仍须遵循既有系统层 worker 排空、快照及密钥保留规则。此 PR 不部署，也不改变线上模型配置。

确定性执行、数据库权限和浏览器夹具验证属于机制证据，不能代替真实 Provider 协议或课程质量验收。
