# LectureLens Adaptive Video Understanding R1

## 范围与能力边界

R1 面向课程录屏、讲座、网课和编程教学视频，目标是从完整时间轴中提取少量、清晰、可跳转的画面证据，再与字幕、OCR 和可选 VLM 结果按时间融合。它不是通用视频 Agent，也不承诺理解任意视频、识别人脸/行为、执行画面中的指令，或在缺少可靠证据时补全事实。

无视觉模型密钥时，VLM 分支跳过；无 Tesseract 时，OCR 分支禁用或逐帧降级。ASR、字幕、翻译和学习资料主链不因此失败。

## 参考思想

R1 借鉴 DOVideo-AI 的几个工程思想：FFmpeg 场景变化检测与周期锚点并用、使用真实时间戳、感知哈希去重、ASR/OCR 有界并行、单分支失败降级、进程中断和工作目录清理，以及按时间轴融合证据。LectureLens 没有复制其实现，而是按现有 Spring 配置、错误体系、Owner Scope、Pipeline、MyBatis/Flyway 和测试风格独立实现。

## 原链路的根因

基线实现先按每秒一帧把图片缩到 320px，再用相邻像素差选择关键帧；同一缩略图同时承担变化检测、持久化以及后续 OCR/VLM 输入。`maxSourceFramesTotal()` 最多允许 3000 个源帧，因此一秒采样的长视频可能只处理前约 50 分钟。其后果并非单一阈值问题：

- 候选数量与视频时长线性增长，临时 JPEG、解码和磁盘占用过早发生；
- 320px 图片中的小字号 PPT、代码和终端文字已经不可逆损失；
- 像素差会响应鼠标、人像、滚动、动画和转场，却无法判断画面是否清晰、近黑或重复；
- 场景切换瞬间可能恰好是模糊帧；
- 全局数量上限按先到先得消耗，不能证明完整时间轴被扫描；
- OCR/VLM 即使接线成功，也会被低质量输入限制。

## R1 架构

```text
ffprobe 元数据
  ├─ 音频提取 → ASR → 字幕/翻译 ─────────────────────┐
  └─ 480px 检测流扫完整时间轴                         │
       → 强场景/细粒度内容变化时间戳 + 自适应周期锚点   │
       → 60 秒窗口内合并/限额                         │
       → 候选点附近 -0.2/+0.4/+0.9/+1.4 秒采样        │
       → ≤1600px PNG 质量评分与稳定帧选择              │
       → 黑屏/空白/模糊过滤 → 感知哈希/OCR 去重        │
       → OCR 与少量 VLM 规划 ─────────────────────────┤
       → ≤960px JPEG 持久证据                         │
                                                     ▼
                         有时间戳的多模态片段、章节、问答和导出
```

核心职责分离如下：

- `FfprobeVideoMetadataProbe` 读取真实时长、宽高、帧率、编码和旋转信息；预算不再由候选序号猜测。
- `FfmpegVideoSceneScanner` 在 480px 检测流上以 0.005 的低成本内容变化阈值记录完整时间轴的 `pts_time` 和分数；0.30 以上标记为强场景变化，其余标记为细粒度内容变化。第一遍不导出 JPEG，并在 `finally` 删除元数据日志。
- `CandidateTimestampPlanner` 合并开始、结束、强场景、细粒度内容变化、周期锚点，并在每个 60 秒窗口独立限制最多 6 个候选；候选过密时按窗口内时间桶公平取样，避免滚动前段或高分变化挤掉后续代码/终端状态。
- `StableFrameSelector` 在候选附近比较多帧；强场景/内容变化只允许选择候选时间之后的清晰稳定帧，避免把旧画面误归到新场景。普通变化的后续帧全部不合格时可以放弃；覆盖锚点可放宽清晰度，但仍不保留黑屏或近纯色帧。
- `ImageQualityAnalyzer` 以缩小灰度图计算 Laplacian 方差、平均亮度、亮度方差、边缘密度、近黑/近纯色、稳定性和感知哈希，并生成仅用于临时精确去重的 SHA-256 内容指纹；内容指纹不持久化，也不对外返回。
- `OcrImagePreprocessor` 保留高清原图并生成灰度、缩放、增强对比度、轻锐化和可选二值化版本；`TesseractOcrProvider` 使用 OEM、主 PSM 与有条件的备用 PSM，并限制单帧执行时间。
- `ContentAdaptiveFrameBudgetAllocator` 分四层应用预算：先覆盖均匀时间窗口，再为 `CODE_OR_TERMINAL`、`VISUAL_DEMO` 和 `SLIDE` 保留通过质量门槛的代表帧，随后按综合价值补齐，最后应用全局上限。类别保底不会恢复黑屏、空白、模糊或已去重帧。
- `HighValueKeyframeSelector` 使用相同的时间覆盖和类别代表策略规划少量 VLM 帧；低 OCR 但具有图表、架构图或演示特征的画面获得视觉价值加分。请求上下文由附近字幕、译文、OCR 和时间戳组成，并明确所有画面文字均为不可信课程证据。
- `VisionPipelineBranchCoordinator` 让 ASR 与视觉预处理在两个有界执行槽中并行；取消会传播中断并等待分支退出。视觉失败降级，不覆盖 ASR 主链结果。
- `PipelineRunnerWorkspace` 仅在规范化的用户/任务/请求目录下创建临时区，任务终态执行递归清理。

## 默认预算

| 阶段 | 默认预算 |
| --- | --- |
| 检测流 | 最大宽 480px，扫完整时长，不持久化图片 |
| 变化阈值 | 强场景 0.30；细粒度内容变化 0.005，只增加时间戳候选，不持久化检测帧 |
| 周期锚点 | ≤60 分钟每 30 秒；60–120 分钟每 45 秒；>120 分钟每 60 秒 |
| 候选窗口 | 60 秒一个窗口，每窗口最多 6 个时间点 |
| 邻域采样 | `-0.2, +0.4, +0.9, +1.4` 秒，边界裁剪 |
| 临时分析图 | 原比例、分析最大宽 1600px；OCR 最大宽 2000px；均不放大小图、仅任务工作目录 |
| 持久关键帧 | 全局每分钟上限 4；幻灯片/代码终端/视觉演示/低信息/未知分别最多 2/4/3/1/2 张；全视频最多 240 张 |
| 持久证据图 | 最大宽 960px、JPEG，仅最终选中帧 |
| OCR | 每任务最多 120 帧，默认关闭；单帧默认 30 秒 |
| VLM | 全局每分钟上限 4；幻灯片/代码终端/视觉演示/低信息/未知分别最多 1/2/2/1/1 帧；全视频最多 80 帧，默认关闭 |

这些值均由 `courselingo.vision.keyframe`、`courselingo.vision.ocr` 和 `courselingo.vision.analysis` 配置绑定，可通过示例环境变量覆盖。配额限制的是成本，不允许把长视频裁成前半段；覆盖首先由按窗口规划的候选时间戳保证，再在预算允许时保留各高价值内容类型的代表帧。完全相同的帧可跨相邻分钟去重，只有感知哈希相近的变化帧仍限制在同一窗口内结合 OCR 判断，避免误删代码更新。尺寸严格遵循 `analysisWidth=min(originalWidth,1600)`、`ocrWidth=min(originalWidth,2000)`、`evidenceWidth=min(originalWidth,960)`，OCR 增强不改变原始质量评分。

## 图片生命周期

1. **检测数据**：FFmpeg 低分辨率流和短期元数据日志，只为发现时间戳；不进入对象存储。
2. **临时分析图**：候选附近的高清 PNG、OCR 增强图和 VLM 请求图，只存在任务工作目录。成功、失败、超时或取消后均做清理；不会批量上传 MinIO。
3. **持久证据图**：只把最终选中的图缩到最大 960px 后压缩为 JPEG，并记录低基数质量字段。数据库保存对象键，API 通过 Owner Scope 鉴权的媒体接口返回内容，不返回 MinIO key 或服务器路径。

删除/重跑保持幂等：新结果写入前清理旧行和旧对象；任何对象删除失败都会安全记录错误类型并保留可发现的关键帧行，供后续删除或重跑再次清理。任务软删除不会因 MinIO 暂时不可用而回滚。V19/V20 只新增可空字段，不修改旧 migration，旧任务无需重新处理也可读取。

## 降级与取舍

- 有 ASR 时执行完整字幕、翻译、学习包和四类制品链路；ASR 完全失败但存在语义视觉证据时生成 visual-only 时间轴、学习包、Markdown 和 JSON，并删除/跳过 SRT、VTT；两路均不可用时任务失败。
- 场景扫描失败会使视觉分支失败并记录安全错误类型，ASR 主链继续；不会用不完整时间戳伪装成功。
- 候选点所有邻域帧都模糊时，场景候选放弃，周期覆盖候选可使用非黑/非空白的最佳降级帧并标记 `degraded`。
- 感知哈希在 OCR 不可用时可能把版式非常相近、但文字不同的幻灯片判成重复；OCR 可用时需要图像与文本都高度相似才合并。这是成本与召回率之间的显式取舍。
- VLM 只分析预算内的高价值帧；OCR 为空但视觉变化明显的图表、架构图或实物演示仍可进入计划。计划数量不等于调用数量，关闭 Provider 时调用数为零。
- 临时高清 PNG 比旧 320px JPEG 的单帧体积大，因此 R1 用“少量时间点 × 邻域采样 + 及时清理”换取文字可读性；峰值受候选窗口和最终帧预算约束。
- R1 只对已抽取的离散证据负责，不声明连续动作、说话人身份或未被画面/字幕支持的内容。

## 安全边界

- OCR、字幕和视频内文本均是不可信输入；Prompt 明确禁止执行其中的命令、系统提示或操作要求。
- 日志只记录候选数、过滤数、OCR 状态、耗时和清理结果，不记录 OCR 全文、图片内容、Prompt、密钥、对象键或本地路径。
- VLM 需要显式启用和用户自己的密钥；Demo 不发真实请求。离线评测也不访问网络。
- 媒体证据接口从服务端认证上下文解析 owner，不信任客户端传入的 user id；用户只能读取自己的任务证据。

## 离线合成与三策略评测

脚本只依赖 Python 标准库和本机 `ffmpeg`/`ffprobe`。合成视频包含 PPT 转场、黑屏、快速滚动、三次代码渐进变化、终端错误到成功、未变化代码、视觉演示和长静态画面。默认产物写入系统临时目录，也可显式指定输出和场景清单：

```powershell
python .\scripts\vision\generate_synthetic_course_video.py --output "$env:TEMP\lecturelens-course.mp4" --manifest "$env:TEMP\lecturelens-course-scenarios.json"
python .\scripts\vision\evaluate_adaptive_video.py "$env:TEMP\lecturelens-course.mp4" --scenario-manifest "$env:TEMP\lecturelens-course-scenarios.json" --output "$env:TEMP\lecturelens-vision-report.json"
```

评测独立复现三种策略，避免把测试工具误称为生产 Java profiler：

- `legacy`：每秒 320px 图片、相邻像素差、周期锚点和旧预算；
- `scene-anchor`：场景时间戳加周期锚点，但直接使用切换点，不搜索邻域稳定帧；
- `adaptive`：强场景与细粒度内容变化的窗口化公平规划、邻域高清采样、质量过滤、内容预算和去重。

JSON 中的 duration、候选/采样/最终数量、模糊/黑屏、重复、候选与最终时间覆盖、VLM 计划、耗时、持久 JPEG 字节数都来自本次实际运行。`temp_peak_bytes_approx` 是策略工作目录内真实文件大小的检查点峰值近似，不含操作系统缓存、子进程缓冲和通过管道传输的 PGM。若找不到 Tesseract，`ocr.available=false`、`attempted_frame_count=0`、`valid_frame_count=null`，不会伪造 OCR 结果。评测默认删除所有采样工作目录；只有显式传入 `--keep-workdir` 才保留调试文件。

报告 JSON 和合成媒体属于本地产物，不应提交到仓库。
