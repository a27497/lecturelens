# LectureLens 产品阶段

基线以开发工作树的 Git SHA 为准。验收时工作树须干净；若有未提交改动，须把 `git diff` 与 `git status --short` 随证据一起保存，否则该 SHA 不能代表被测源码。现有 Study Agent 实验、源码身份和质量证据见 [AGENTS.md](../AGENTS.md) 与 [FINAL_AU](../eval/phase-completion/FINAL_AU.md)。

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| Phase 0 | 核对基线、身份清单、已有竞品观察和验证入口 | 指令引用可核对，记录提交和测试证据，PR 的 CI 真实跑绿。文档和配置变更由协调者核对 |
| L2 性能与可靠性 | 先用现有 harness 测检索和 Run，必要时加长跑 | 报告并发档、分母、吞吐、P50/P95、预期拒绝、异常和恢复结果。有证据再调参或修复 |
| L1 工程审计与精简 | 对 Java、前端、脚本和非冻结 Python 模块做只读扫描，再人工分诊 | 按已确认问题提交小改动，对涉及入口做回归。保护冻结候选、清单、fixture 和既有证据 |
| L3 产品体验 | 基于 YouLearn 观察收敛视频、字幕、Tutor 与练习 | 代表性用户可以完成学习流程，错误和恢复路径有浏览器证据 |
| L4 AI Benchmark | 固定课程、任务、模型、Judge 和预算 | 发布可复算的正确率、引用支持率、拒答、费用、延迟及适用范围 |
| L5 发布与展示 | 公网 Demo、README、架构图和演示 | 从新用户入口核验部署、可复现性及能力说明 |

L2 根据 [并发契约](AGENT_CONCURRENCY.md) 分别计量槽满时的有界 `503 Retrieval busy`、`Retry-After` 和异常失败，测量对索引、检索和 Run 的相互影响。交付一页并发档、成功率、吞吐、P50/P95 与环境的数据表，参数调整最多两项。默认值符合实测负载时可直接通过验收。L1 清理任务将整个 `agent-service/src/lecturelens_agent/study/` 排除在范围外，Knip、Vulture、jscpd 均为 report-only。

每个阶段记录候选提交、环境、命令、退出码、计数、证据和独立审查结论。Real、Mock、Offline 和 NOT_RUN 分别标注。核心验收完成后才切换主阶段。

## 费用与停止条件

项目所有者已长期授权真实模型调用，每次请求上限 USD 10，本项目累计上限 USD 200。阶段软分配为 L2 USD 10、L4 USD 120、预留 USD 70，分配与消耗记入协调账本 `agent-control/SPEND.md`。限额内直接执行并在阶段结果报告实际花费。

单阶段最多修复两轮。第二轮仍未达标时记 PARTIAL，把后续动作写入下一阶段。同一提示词或配置已跑两轮且指标无变化、批次缺少预先声明的样本数或停止条件、仅为边际提升重跑完整评测、阶段分配耗尽时停止。每批调用规模与提供方重试次数均须有界。
