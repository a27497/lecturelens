## 修改与 Agent 行为

- 学习目标仍是基于课程解释并生成两道不同练习。模型选择检索、补读、提交练习或证据不足工具；拒绝的草稿形成观察，交给模型决定修订或补查。通过检查后保存产物，失败有明确终态。
- 复核网络输出缩小为 `{"issues":[]}` 或有限问题代码，由本地生成最多 400 字符的修订提示；拒答候选只判断是否错误拒答。保留 300 token 上限。
- 按解释、问题、答案、评分点检查显式行内引用编号是否属于该字段声明的引用集合。发现不一致时拒绝候选并给出反馈，不调用付费语义复核。这是语法一致性检查，不证明内容有据。
- 提示词要求检查完整执行输出、每个声明的课程支持及目标语言。模型仍可能忽略要求，结果如下。
- C 在决策返回非法工具格式时，最多给一次明确格式纠正观察；错误响应的工具均不执行，下一次调用仍计入原有预算。不重试鉴权、网络、限流、截断或复核错误，不自动切换模型。页面显示正在尝试纠正。
- 保留失败调用的已知 token 用量及脱敏诊断分类；不把失败计为零成本。原始响应、密钥和反馈正文不写入公开事件。

每题仍为 90 秒、6 次模型调用、8 次工具调用、64,000 保守 token 预留、最多两份候选；决策输出 900 tokens。预算、授权、版本检查、取消、checkpoint 恢复及产物幂等性保留。
