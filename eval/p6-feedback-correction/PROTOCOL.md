# P6：证据反馈与正确订正的测量预案

本轮只检验测量机制。**不证明教学效果，不把 Mock、CI、核对点击或脚本答案正确当作学习成功。**

唯一研究问题：学生借助 Study Agent 的课程证据反馈，是否比只阅读同一课程自行检查，更容易发现初答知识错误，并完成有课程证据支持的正确订正？不测掌握率、隔天迁移或长期记忆。

## 条件、比较与样本

- A（reading）：初答保存后，仅看同一课程/原文自查，再保存新版作答。不得打开 Agent 反馈、参考答案、Tutor 或外部资料。
- B（feedback）：初答保存后，显式请求一次绑定该初答版本的证据反馈；核对来源、记录同意或异议，再保存新版作答。无第二次反馈，避免混入额外辅导剂量。
- 两组相同题干、材料、初答限时3分钟、干预限时5分钟（B含等待）、再答限时3分钟。到时允许保存未改答案的新版本。超时、退出、反馈失败分别保留，不用“重新来一次”替换。另记等待时间、实际阅读时间及外部帮助；反馈耗时是产品成本。
- 小样本先以4人为平衡目标，可招募3–5人；每人4题且每题仅做一次。所有人先有2分钟非测试题界面熟悉，不展示测试答案。正式题使用holdout的h1–h4，开发题仅练习记录流程。

预定分配表（A/B随受试者匿名编号分配；先招募后用抽签把人映射到编号，保存随机种子/抽签记录）：

| 编号 | 第1题 | 第2题 | 第3题 | 第4题 |
| --- | --- | --- | --- | --- |
| P1 | h1 A | h2 B | h3 A | h4 B |
| P2 | h2 A | h1 B | h4 A | h3 B |
| P3 | h3 B | h4 A | h1 B | h2 A |
| P4 | h4 B | h3 A | h2 B | h1 A |
| P5（如有） | h1 B | h2 A | h3 B | h4 A |

4人时每题在两条件各出现2次，每个顺序位置也均有A/B；个人不重复同题，减少直接记忆效应。3/5人不完全平衡，按题、顺序和人列出原始结果，不假装平衡。同一课程题间仍可能迁移，四题难度不同；这不是消除所有混杂的随机对照试验。不给同一学生同题先A后B。含证据不足题，单独报告，不与可求解题的领域正确率混称。

合成材料短、错误可能太少：若无人初答错误，错误发现/订正率为NA，不能用全对声称干预有益。预定的学生初答只用于机制和Provider质量评测；真人必须自己作答，不让他们扮演预置错误。后续换真实课程须重新独立制题、冻结，旧数据不算未见课程。

## 每个trial的记录流程

1. 同意参与、匿名编号、分配条件、题目、顺序、设备尺寸、课程revision、开始时间进入研究侧sidecar。不要收姓名/邮箱。真实试用数据放私有目录，不提交Git。
2. 初答：使用已有练习产物，`SAVE_ATTEMPT`保存v1；记录owner/course/revision/session/run/artifact/question_index及attempt_id。题目必须与冻结题干逐字匹配。两条件需要同样的固定题目；离线质量回放可以复用既有评测的种子产物方式；当前Mock演练由确定性Provider创建产物，不是测出题能力。真人试用必须在隔离环境由主持人准备并逐题确认冻结题目，不让学生看种子答案。
3. A读取课程；B执行`START_FEEDBACK(attempt_id=v1)`，保存feedback Run ID、feedback_id、status和调用计数。失败也记录，停止本题B干预，不补抽一条好反馈。不能把v2后的旧反馈当成v2的新反馈。
4. 自查/反馈核对期间：主持人记来源ID、revision、定位时间与操作时刻。B使用`SAVE_FEEDBACK_NOTE`记录acknowledged/disputed及真实理由；A没有这类记录，研究侧自查表提供等长的理由输入。主持人不提示正确性。
5. **再答前**两条件均写“我原来哪句话有问题、为什么/没有发现什么问题”；sidecar discovery保存原话和时刻。不把反馈指出错误替代为学生发现错误。再答保存v2，即使完全相同也保存新版；`final_evidence`绑定v2 attempt_id，学生填写每项订正的来源ID及为何支持；主持人只帮助标ID，不提供推理。最终字段不直接给学生金标准fact_id，评分者导入时映射fact_id并保留学生原话。
6. 导出使用明确Run ID、attempt ID；从`ATTEMPT_HISTORY`分页取全量不可变版本，从具体反馈Run的`READ`取绑定和原文，从`FEEDBACK_NOTES`分页取全部核对历史。不靠最近20条列表猜“无反馈”。核对/作答的created_at来自PostgreSQL；暴露、发现、来源点击与计时来自有来源标记的研究sidecar，**不伪装成产品遥测**。
7. 导出前后比较每Session的Run/model_calls/tool_calls；刷新、历史、回看、读取来源不得增加它们。完成后以新Store回读，验证不是只拿写入响应拼装。保存原始JSON、源码身份、输入冻结hash、导出hash及评分文件hash。数据库导出不读模型配置/凭据字段。

已有字段和缺口见[BASELINE.md](BASELINE.md)。研究侧表单见[FORMS.md](FORMS.md)。不开发新产品功能。主产品未持久化“真的看懂”，人工观察也不能直接证明。

## 评分与指标

标准答案由本轮独立合成课程派生，先于任何P6反馈输出冻结：关键事实点、等价表述、必需段落与常见错误见各split的standard.json；不使用Agent参考答案或运行时复核结论作权威。**这是一份AI编写的预定评分标准，尚未经过真人双评校准。**

两名评分者先各自读课程和rubric，用开发示例校准含义，再独立评分正式数据。隐藏条件、学生身份、顺序和初答/再答角色，先用随机答卷ID评事实正确性；该部分封存后再揭盲到配对、反馈和核对记录，评发现、支持和误导。两人不得相互看分或看运行时复核结论。保存R1/R2原分后算一致性，再第三人裁决分歧，裁决另存，不改原分。没有两人则标SINGLE_RATER，不能称独立人工一致性通过。

事实标签：correct / incorrect / missing / unsupported。按语义判定，接受等价表述，不做关键词命中；关键点存在相反断言时不能给correct。完整rubric见[rubric.json](rubric.json)。

| 指标 | 分子 / 分母 | 限制 |
| --- | --- | --- |
| 初答事实正确性 | 初答correct点 / 全部必需事实点 | 按题和可回答性分层 |
| 错误发现率 | 初答非correct且学生在再答前明确识别的点 / 初答非correct点 | 非correct包括遗漏和无据断言；另保留错误类型 |
| 订正后事实正确率 | 再答correct点 / 全部必需事实点 | 另报整题全对数/完成题数 |
| 订正率 | 初答非correct→再答correct点 / 初答非correct点 | 未改、改成另一错都非成功 |
| 有证据支持的订正 | 已订正且学生提供必需来源+理由、评分者确认支持的点 / 全部已订正点 | 点击来源、引用ID存在均不够 |
| 反馈误导信号 | B初答correct→再答非correct点 / B初答correct点 | 另逐例评错误反馈与接受理由；时序关联不等于因果归因 |
| 漏检 | B初答非correct且反馈未准确指出的点 / B初答非correct点 | 拒答不能视为指出具体错误 |
| 漏检错误保留 | 漏检且再答仍非correct点 / 全部漏检点 | 不能推断保留一定由反馈造成 |
| 错误接受 | 明确接受实质错误反馈的B题 / 存在实质错误反馈的B题 | 含错误拒答声明；与改错率、漏检分列，不相加 |
| 错误拒答 | 课程证据充分却输出证据不足的B题 / 证据充分的B题 | 运行失败不算拒答成功 |
| 不足证据诚实性 | 明确边界、说清缺何依据且无杜撰的题 / 不足证据题 | 人的再答为主；反馈本身由独立评分理由逐例检查 |

`measure.py score`给出各条件分子/分母、逐例评分与hash；零分母是null，不是100%。incomplete_trials按条件/原因另列，主表分母是完成题，同时报告分配题数、缺失率，并做把缺失当未成功的保守计数。任何协议排除都留记录，不事后缩分母造好结果。若严重缺失/污染，停在可行性描述，不比较效果。

一致性：逐trial+事实+阶段配对，原始一致率=相同标签数/全部双评分标签数；Cohen κ=(观察一致−偶然一致)/(1−偶然一致)，偶然一致=各标签两人边际比例乘积之和。全同一标签导致分母0时κ=null；集合/二元字段另算逐字段一致率。3–5人不预设“κ通过即证明标准可靠”；报告混淆、分歧与裁决理由。示例打分见example-ratings.json前两例；其余故意失败例用于检测计分器，不是真人评分。

## 无效结论的风险

练习/顺序迁移、题目难度和既有知识差异、反馈与阅读耗时不同、泄漏金标准或参考答案、主持人暗示、参与者迎合、只招熟悉工具者、退出只删坏例、反馈失败后无限重试、把旧反馈归给新版、同人同题重复、评分者看到条件、课程片段过短且无知识错误、用脚本回答代替真人、将正确拒答当领域掌握，都会削弱或使比较无效。用分配表、计时、盲评、完整失败记录和逐例分析缓解，不宣称已消除。

只做描述性统计和个案分析；不作显著性检验、群体效应、因果收益或隔天保留结论。一个学生的多题不是多个独立学生。

## 三类证据与下一阶段闸门

| 证据 | 能回答 | 不能回答 | 本轮 |
| --- | --- | --- | --- |
| Mock/确定性Provider+真实PG | 命令、版本、绑定、引用导出、只读无副作用、失败可计数 | 反馈智能、真人发现/理解、教学收益 | 已运行；故意错误反馈会被演示复核接受 |
| 独立人工评分+真人试用 | 该样本订正是否正确、理由受证据支持、误导个案、流程可行性 | 一般教学效果、显著性、长期迁移 | NOT_RUN；无真人评分者/受试者 |
| 真实Provider | 冻结配置下实际反馈质量、误拒答/漏检/误导、成本与延迟 | 学生是否理解、教学效果 | NOT_RUN；需用户另行授权 |

**唯一推荐下一行动：先授权一次有界真实Provider反馈质量预检，再决定真人试用。** 理由：测量链路可以用sidecar补齐，但故意坏反馈也能在Mock复核通过；当前真实反馈是否会误导尚未知，不宜把历史AU结论继承为本轮质量保证。真人试用可执行材料已准备，不等于已获招募或调用授权。

建议首次预检16份新合成初答：8开发（正确、单错、遗漏、混淆、等价表述、证据不足等）+8独立留出；当前冻结题可作开发机制参考，正式留出由另一位制题者在候选冻结后新建，避免已消费数据。每Run最多6次模型调用（含决策/独立依据/复核/修订），合计**最多96次外部尝试**；工具≤8、候选≤2、64k保守预留、90秒/Run沿用运行时，不提高。取消、超时、不明结果、重试都计调用；未知费用停止，保留失败，不自动加预算。冻结完整main/代码清单、runner hash、模型路由/参数、任务和账本后才能跑。历史授权不能继承。

费用只估算不查询账户/凭据：C=Σ[(实际输入tokens×该用途输入单价 + 实际输出tokens×该用途输出单价)/1,000,000]，生成/复核不同单价分算。规划场景每调用输入6000、输出900，96次为576000输入+86400输出；若**假设**单价2/8货币单位/百万token，则约1.8432单位；这不是任何供应商现价/报价。以用户选择的Provider当日官方价格替换，包含未返回usage的最坏预留及余量，用户明确“96次与金额上限两者先到即停”。64k是运行时保守预算，不直接当账单或货币硬限。未选模型/价格/币种与费用上限前无实际报价，当前零调用。质量预检不做本轮教学收益结论。

之后如质量可用，再单独授权招募3–5人；不把Mock证据反馈当作在线Agent效果。人工试用可用已审核并冻结的真实反馈回放，需明确此时测的是固定反馈条件而非实时模型可靠性。若采用实时反馈，另行冻结版本和调用/费用预算。
