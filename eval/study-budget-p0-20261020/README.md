## 根因

1. `act(search_course_evidence)` 无条件调用 `course_methods_v1`。虽然五条来源重叠且方法、覆盖依据仍在，两次搜索仍各付一次候选不可见的方法观察。原窗口复用路径只检查方法 ID 是否保留，搜索没有同等复用。
2. 原决策视图只限制每条 600 **字符**，八条中文可能占 14,400 UTF-8 字节；schema、系统提示、历史工具参数还需额外预留。旧历史工具结果同时重复携带过时的覆盖观察。64,000 是累计保守预留，实际 usage 较低并不会退还预留。
3. 原估算还包含实际 HTTP 紧凑 JSON 不发送的排版空格与 schema 的 ASCII 转义。修正此项单独不足以完成链路。
4. journal 在请求前原子拒绝超额预留，因此没有下一次 `model_started`；事务回滚后原来只留下通用 `RUN_BUDGET_EXCEEDED`，缺少具体资源、申请量与调用位置。

默认六次模型、八次工具、90 秒 deadline 和 64,000 预留上限均不增加。没有依据本次结果提出提高上限：先前的冗余调用和字符/字节预算失配已有可修复依赖；增加上限会扩大累计供应商成本及错误循环可用额度。

## 修复及保留边界

- 搜索与窗口补读共用方法观察复用条件：仅限同一 Run、同一 practice_kind、原判断可回答且含方法，全部方法与覆盖依据仍在当前授权结果中，且其观察文本（最多 1,200 字符）指纹相同。来源移除/改变、主题切换、否定观察和缺少指纹的旧记录重新观察。新增来源仍供下一次决策选择；被候选字段引用时，按原契约进入该字段的最终复核。复用不是对新来源的语义判断，未引用的新片段也不被冒充为字段支持。
- 决策证据正文共计最多 6,000 UTF-8 字节。最多两个方法来源保留原 600 字符视图（即使四字节 Unicode 也至多占 4,800 字节）；最近显式补读锚点优先使用剩余额度，为其他来源预留短预览份额（每条至多 64 字节）后再共享余额，保留 ID、时间范围和截断标记。短片段让出剩余额度，显式补读能展开预览。决策只显示最新覆盖观察，完整原始观察/来源指纹保留在工具日志与 checkpoint。
- 预留按 HTTP 所用紧凑 JSON 的消息/schema 字节加原有输出上限计算。仍是保守估算，不是计费 token，不根据缺失/较低 usage 释放额度；既有 journal 预留不重算。
- 每份候选的独立质量复核及每条最多 1,200 字符的权威来源输入不变。引用映射、逐字段来源、Java 权属/revision/删除检查、候选数、取消、deadline、幂等和恢复 journal 均保留。
- `BudgetExceeded` 携带有限诊断；在终态事务内提交 `budget_rejected`，避免拒绝事务回滚丢失原因。包含 resource reason、申请/已用/剩余预留、调用/工具上限，以及可用的 purpose/review_stage、operation_key、node/checkpoint 和输入字节/输出额度。无课程正文、问题、答案或凭据；公开错误码兼容。
