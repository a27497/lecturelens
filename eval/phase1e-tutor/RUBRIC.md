## Record three separate verdicts

1. **Retrieval.** Compare the prepared, re-READ evidence in the private PG checkpoint with the packet texts after Java `evidence-v1` whitespace normalization. Require at least one excerpt from each `required_evidence` group. Record FULL, PARTIAL, MISS, EXPECTED_GAP, UNMAPPED or UNOBSERVED. Compare what reached the model with the frozen packet, not what the response cites. The refusal task intentionally has no sufficient excerpt, so irrelevant retrieved passages are compatible with EXPECTED_GAP.
2. **Execution.** Record whether there was a generated, published reply, a deterministic abstention, a protocol rejection, an execution failure or an unobserved position. Report timeouts, insufficient budget, usage/identity errors, cancellation and source changes separately from protocol failures. Retain the raw draft privately where the journal recorded it. A position skipped after a stop stays in the denominator.
3. **Teaching quality.** Independently review generated replies with FULL coverage and generated abstentions with EXPECTED_GAP. For PARTIAL or MISS, record any unsupported behavior and the missing groups, and leave teaching quality with complete evidence unobserved. A deterministic refusal is a controller outcome. For generated replies, match the required outcome and mark each listed requirement PASS, FAIL or UNCERTAIN, with a short answer span or exact omission and an evidence locator. Check each substantive course claim against the cited current excerpt, not merely an ID or an adjacent passage. An arithmetic/example derivation may use learner inputs if it names the source rule and distinguishes the new result from source facts.

A turn passes strictly when the generated reply is published, has the expected outcome and appropriate coverage, and every required check and substantive course attribution passes. A Socratic prompt must advance the learner's specific reasoning and withhold the requested solution. A generic or answer-revealing question fails even with correct formatting. Keep disagreements and UNCERTAIN results in the evidence. An unresolved item cannot pass. Accept equivalent correct implementations and formatting. Compare fixed code and computations with [the executable references](references.py). Use a sandbox for any generated code a reviewer elects to run.

Use a human subject-matter reviewer, or two independent cross-reviews with a human adjudicating differences. Give reviewers the frozen questions, previous published dialogue, current retrieved evidence with IDs, response, clauses and executed reference outputs. Keep execution/config labels, prior v19 answers and prior scores out of the initial semantic review. Ask for each rule verdict and its justification before showing the negative controls or the other review. Record reviewer identity/type, disagreements and all excluded positions. No paid reviewer is part of E1.

The SQL negative control uses a real available GROUP BY excerpt to support a false claim about `COUNT(weight)`. It must fail semantic review even when retrieval was FULL and the citation ID passes. The companion fixture drops the NULL excerpt and must produce MISS. These authored controls validate the separation of the checks. They supply zero evidence about model teaching quality.

For E3, report strict pass counts separately for exposed regression (3), new development (3) and holdout (4), with the retrieval and execution outcomes alongside. Require all ten scheduled positions and all four holdout turns to pass for this bounded acceptance. Report any other result with its failing or unobserved turns. Treat success as evidence for these packets only.
