# 逐字段支持与拒答依据修复

承接 [真实闭环结果](../learning-loop/RESULTS.md)，本轮先完成质量修复及验收，不引入自适应后续练习、自动评分或长期记忆。P/Q 已消费结果和失败保持不变；真实模型沿用用户已授权的隔离百炼 qwen3-max/max，总调用不设上限，每 Run 预算不变。

## 学习目标与实现

学习者希望从课程得到有据可查的解释、两类练习，或诚实的证据不足结论。模型仍选择搜索、补读、提交练习或拒答；新变化为：

- 通用搜索结果增加独立的课程支持观察，仅输入学习目标与本次授权证据。明确区分直接支持、已演示方法可迁移、主题缺失；观察为可质疑的模型输出，不能覆盖 Evidence 权威或自动认定正确。
- 练习复核按字段分别提供自己的证据和原始作答点；每个字段必须保存课程事实观察、绑定的 Evidence ID、问题分类及完整的短纠正意见。禁止借用其他字段的来源。
- 拒答复核不接触候选拒答理由，只根据目标和观察判断覆盖范围。缺失项必须绑定目标原文。
- 已计算题继续先验证同一题目/程序的计算证明，再隐藏其确定答案；语义复核不得覆盖确定计算。旧协议保留用于历史回放。

R/S 开发失败后的具体调整：逐字段来源改用互不混用的本地标识，校验后映射回权威 Evidence ID；通用检索用六个排名片段并为最多两个相邻片段留位，在两个窗口上限内按课程时间补齐步骤。非计算题必须记录预期答案和原答案匹配判断，不匹配必须拒绝；这仍是模型语义判断，不是独立人工评分。明确要求“新字符串”时，所有多字符输入均已出现在观察原文中的程序会触发预算内重拟；改了输入不代表通过内容验收。新协议单次复核输出上限900，持久预留使用同一数值，每 Run 原有总预算不变。

新观察、拒绝意见和成功产物仍写入 Python/PostgreSQL 原有工具日志与事务；预算、取消、版本栅栏、幂等、执行锁和 checkpoint 继续约束全部调用。缺少来源、契约不合法、预算耗尽或任务终止仍然停止，不能伪造完成。

## 验证顺序

1. 有意义的协议及真实独立 PostgreSQL 测试：逐字段权属、重复/缺失字段、候选理由隔离、计算证明、调用预算、迟到取消、工具提交后恢复且不重复支持检查。
2. 冻结候选，对已消费的六题及课堂例题复用问题回归，逐题核查内容、引用和真实任务完成，不把 Run 成功当质量通过。
3. 开发回归通过后再冻结新目标，所有支持题的解释/问题/答案及逐字段来源都正确、课程外可靠拒答；失败保留。开发题或旧保留题再次运行只是回归。
4. 结果、调用账本、源码/输入哈希、质量限制与部署边界同步。未满足门槛不发布，不声称自动评分或通用教学可靠性。
