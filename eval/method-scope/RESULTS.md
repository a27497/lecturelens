## 实现

学习者需要用课程已经演示的方法完成新的练习。模型仍选择搜索、补读、出题或拒答；新增的观察会影响下一步选择：

- 通用课程搜索和补读记录最多两项方法：操作、输入、输出及来源编号。Python 从本次授权 Evidence 回填原始文本，模型不再转抄字幕。来源编号和文本绑定可检查，方法语义是否正确仍依赖模型。
- 模型必须选择当前观察中的方法生成通用应用题。补读重新形成观察；重新搜索清除旧选择。缺失方法或来源不再可见时停止；不能任意填一个编号绕过。
- 最后复核将题目实际要求的操作、输出与预先记录的方法比较，作为独立必填对象返回。数学答案正确不能抵消方法越界；范围不支持时允许直接拒绝而不求解越界题。
- 方法、模型选择、原始来源与判断结果写入现有私有工具日志，checkpoint 恢复复用已提交观察。公共产物不暴露内部计划。旧无方法记录保留历史回放兼容。

新增协议只发给需要它的调用，避免无关任务的请求变大而耗尽修订预算。每 Run 的6次模型、8次工具、64k保守预留、90秒、最多2份候选限制不变；取消、所有权、版本栅栏和幂等继续由原协议约束。实现位于 Python Agent，无 Java/前端或表所有权扩张。

## 新保留八题

X 的七题开发核查结束后，才冻结五个线性代数目标和三个字符串目标。源码保持不变，通过真实认证 Java 网关、实际课程 Evidence 和隔离 qwen3-max/max 执行；未注入产物。这些课程已经用于开发，因此仅是**已见课程的新目标**。

| 目标 | 严格质量 | 说明 |
| --- | --- | --- |
| 负坐标与坐标顺序 | 通过 | 新负坐标代入、求值及验证一致，引用支持相同方法 |
| 两个候选点分别检查 | 失败 | 前置观察文字超长导致协议失败；原始判断也错误要求课程存在完全相同的双点题 |
| 候选点使两个方程都不成立 | 失败 | 生成题只让一个方程不成立，复核漏掉用户明确条件 |
| 重合/平行解集分类 | 失败 | 标记为拒答，却在括号中给出课程未教的“无穷多解/无解”答案 |
| 最小二乘 | 通过 | 没有提供缺失的最小二乘方法；拒答中有多余引用标签和几何措辞，记为呈现缺陷 |
| 重新绑定前后各打印一次 | 通过 | `world`、`World` 两行输出与确定计算一致 |
| 连续两次重新绑定 | 通过 | `apple → apply → apply!`，两次重新绑定、最终输出及课程操作一致 |
| 字符串驻留与 `is` | 通过 | 不以不可变性和重新绑定推导缺失的身份比较机制 |

所有通过项核对实际题目、私有答案、用户条件和各字段自身引用。判断为 Codex 按源文核查，**不是独立人工盲评或自动评分有效性证明**。特别是拒答分类题，不能因最终产物类型为 `insufficient_evidence` 而计作通过。逐项证据见 [新保留审阅](X-holdout-review.json)；八题现均已消费，未来重跑只能算回归。
