## 次数和资源上限

- 最多一个新出题 Run、一个已保存作答、一个新反馈 Run；没有额外连通性探测、自由问答、对照模型或自动新建 Run。
- 每个 Run 保留六次模型调用、八次工具预算扣减、64,000 累计保守预留和默认 90 秒 deadline。两 Run 合计至多 **12 次模型请求、16 次工具预算扣减、128,000 预留**。取消、checkpoint 和幂等围栏保留。
- 出题请求输出上限为原决策 900、目标复核 1200（其他模式按原契约）；反馈请求为 900。以各调用最大值计，两 Run 的输出额度总上界为 **12,600 tokens**，不承诺它就是实际使用量或费用。
- 内置格式纠正/反馈失败处理仍受上述六次持久模型预算约束，不另赠调用。外层自动重跑为零；服务返回失败、预算耗尽或调用结果未知时停止，不换模型或通过新 request_key 继续试到成功。
- 健康确定性夹具使用九次请求只是当前机制观察，不能把它当成真实模型一定只需九次的保证。
