# 课程求解优先候选 M（2026-09-19）

**本轮完成实现与评测，但没有改善整体复核质量，M 不发布。** 已见八题判对 **5/8**，新八题仅 **2/8**；新题同时要求反馈可靠时仅 **1/8**。两条预置草稿的真实修订链路中，1 条有效修订并保存，1 条首次复核协议失败。线上 C 与 `qwen-plus` 决策 / `qwen3-max` 复核配置不变，L2.2 尚未完成，不进入 L3。

本轮一个冻结候选，**20 次真实调用**：16 次直接复核，4 次真实复核/修订；另外四次固定检索/初稿注入不是外部模型调用。没有看过结果后修改候选、重试覆盖失败或重计 [L 的成绩](FEEDBACK_PRESERVATION.md)。

## 实现与实际边界

L 的失败包括：评分规则错误时，复核器要求删除正确输出 None，所选课程引文却支持该输出。本轮在 [quality.py](../../agent-service/src/lecturelens_agent/study/quality.py) 中加入先输出的 `answer_checks`：每题简短的课程求解答案、是否匹配原参考答案、该题自己的课程片段编号。随后再判断原参考答案的评分规则和其他问题。

答案不匹配时，程序直接使用求解答案生成纠正，原答案的位置由程序按题序确定；`findings` 不再允许另发 `incorrect_answer` 编辑指令。未知、重复、非课程或不属于该题引用的求解锚点会导致校验失败。求解答案作为模型意见保存在私有 `answer_observations`，引文由真实输入回填；它不被包装成课程原文或已验证事实。

原有 `rubric_observations` 继续单独保存。决策模型可同时看到课程求解、事实反馈与原评分规则，选择修改草稿或补查；接受后保存练习，否则明确停止。观察与引用继续经过规范 Evidence ID、持久化、checkpoint 恢复及短编号映射，公开事件不带正文。

**这仍是同一次模型调用，输入中仍有原答案和评分规则。** “先独立求解”是提示与输出结构要求，不是上下文隔离，也不是第二个独立审查器。程序只验证结构、原文与引用范围，不能证明模型正确理解了规则或引文。两题各最多 100 字求解答案、最多两个课程片段；共享原有 300 输出 tokens 和 Run 预算，没有增加调用或重试额度。

[真实修订脚本](../../scripts/eval/pilot-managed-study.py)也补齐了诊断：在复核校验前保存已解析的工具参数及 usage，失败时保留安全诊断，并遮盖客户端密钥；调用结束恢复原客户端方法。这些记录仅存于 Git 忽略目录。截断、非法 JSON 等在底层请求解析之前失败的响应仍没有原始正文记录，不能宣称所有网络失败都可完整还原。

协议失败不算正确拒绝。逐题检查由 Codex 对照完整草稿和课程引用完成，不是盲评或人工金标。报告分别保留二元判定、反馈验收与对失败原始参数的离线诊断。

16 次原始响应中的 32 份课程求解子答案及其匹配判断均符合本轮预标注，但这**只说明求解子项**，不代表最终复核成功，也不证明每个选择的短引文本身足以单独证明整个答案。后续输出造成了主要失败：

- **重复问题报告**：rl-02、rl-06、rm-04、rm-06 已经正确给出答案纠正，又在 `findings` 中对同题报告 `unsupported_question`。这既违反每字段一个主问题的契约，又把“答案不完整”和“课程不支持问题”混淆。校验失败完整保留，没有忽略额外问题后重计成功。
- **错误引用范围**：rl-04、rm-08 的额外问题报告选择了该字段未声明的 e6，导致协议失败。rl-04 虽不再要求删除正确 None，仍添加了无据的解释批评。
- **条件规则误判**：rm-01、rm-05、rm-07 的程序只打印 open，参考答案也只有 open。规则“额外写出 None 则零分”并不适用，却被模型标为 `denies_credit`，三份正确草稿因此误拒绝。
- **无据的额外批评仍存在**：rm-02 应因评分冲突被拒绝，但解释明明说返回值不会自动显示，模型却要求删除“None 自动显示”的说法。二元判定正确，反馈验收失败。

直接复核合计输入 61,998、输出 2,692 tokens，单次 30 秒、300 输出 tokens、temperature=0.2、无重试，无缺失 usage。L 曾在同一已见八题判对 8/8，M 本次降为 5/8；不是同期随机 A/B，但足以阻止宣称净改善。不同轮的新题也不能直接当作同一测试集比较。

## 实际修订与持久化

[两份种子草稿及验收要求](repair-m-cases.json)在任何 M 调用之前选定。它们是已见开发失败；检索和第一次提交由脚本固定，后续复核/决策才是真实模型。实际运行 LangGraph 和独立 `lecturelens_agent_test` PostgreSQL；固定公开 Evidence，不验证自主生成、Java 鉴权、召回、媒体摄取或浏览器。

| 草稿 | 结果 | 外部真实调用 | Run 调用预留（含两次注入） | token 预留 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| rl-04：正确答案遇到矛盾规则 | **有效修订并保存** | 3 | 5 | 62,260 | 14.45 秒 |
| rk-06：答案与规则同时漏外层打印 | 首次复核协议失败，无产物 | 1 | 3 | 31,347 | 4.70 秒 |

rl-04 的真实决策上下文包含正确的 `ready / ready / None` 求解与原文。模型保留原题及全部正确答案，只删除评分中的矛盾零分条款；再次复核接受后保存。按预声明标准检查，算有效修订。初次复核仍把规则问题错标为 `citation_mismatch`，不能据最终产物正确追认所有分类正确，也不能把这次成功替代直接复核同题的失败。

rk-06 的原始参数现在可定位：课程求解为正确的 `with return / True`，但又对 question_2 重复报告 `unsupported_question`，额外 finding 还只有课程锚点、没有候选字段锚点。主校验先在重复字段处失败，未进入修订。L 同题失败时没有保存这些参数；本次结果不能倒推 L 当时具体失败原因。

[修订报告](report-m-repair.json)记录了完整边界。四次真实调用合计输入 14,874、输出 745 tokens；解析后的四份原始响应全部留存。原始记录落盘后，脚本清理了本轮专属会话、Run、产物、工具结果、checkpoint、临时模型连接和路由，回查剩余零行。线上仅只读取得指定用户配置。

成功 Run 的 token 预留已达 62,260，接近原有 64,000 上限；不能假设更长草稿或额外补查仍能完成。本轮不扩大预算来掩盖这一限制。
