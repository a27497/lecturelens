## 决策与下一步

这组结果支持优先修复核方法，不能证明整个 `qwen3-max` 模型普遍不具备复核能力，也没有提供更换模型后会改善的证据。本轮保持线上 C 与个人模型配置，E 仍是未发布候选。

下一轮范围应收窄为：用草稿自己的标准答案检查评分点是否给出矛盾结论；要求拒绝意见定位到具体主张和证据片段，区分“证据没写”和“漏读证据”。先在这组开发样本回归，明确误接受与误拒绝，再用新保留样本检验；不直接扩大出题、自动评分或记忆功能。本轮没有执行模型替换、Agent 修订链路或保留集测试。

## 冻结与范围

- [8 份固定草稿及预标注](cases.json)，4 份应接受、4 份应拒绝。预标注来自 Codex 对照 MIT 课程字幕的检查，不是盲评或人工金标。全部为开发样本，来源片段已见；同主题样本和对照并非独立抽样。
- 三组正确/错误草稿对：完整函数输出、评分点一致性、解释是否有课程依据。错误版本只变动对应字段。另有合理拒答和错误拒答各一份。
- C 使用线上冻结代码；E 使用未发布的候选代码。模型均为账号已配置的 `qwen3-max`，不更换服务、连接或用途。不同的是整个复核输入和输出契约，不能把差异单独归因于某句提示词。
- 复用 [MIT 来源清单](../study-v2/sources.json) 的 SHA 校验和片段构造器。原始字幕与实际请求/响应留在 Git 忽略目录；没有发送私人课程。
- 输入只包含目标、草稿和 Evidence 及版本自身生成的观察；case ID、分组、预期判定、预标注理由不发送给提供商。固定顺序 seed=917，两版相同。
- 调用前冻结两版源码、题集、脚本摘要。每版 8 次、合计 16 次调用，每次最多 30 秒、300 输出 tokens，temperature=0.2，无重试。C 整组后运行 E 整组；模型别名和远端算力不具备不可变证明，不能作受控速度比较。
- 通过 ModelRegistry 只读冻结账号配置，直接调用生产 ChatProvider.review。未启动 LangGraph Run，没有生成新练习、发布产物或数据库写入；无需创建测试账号和清理 Session。

## 判定方式

报告分别记录接受/拒绝与预标注是否一致、误接受、误拒绝、协议失败，以及是否返回预标注允许的问题代码。拒绝错误草稿但给出无关代码，不计为命中目标错误；返回允许代码仍不代表反馈具体有效，需另行检查。超时或协议失败记为错误，不自动算成正确拒绝。失败不会被后续成功覆盖。

完整输出对照显式询问两行输出，属于较明确的诊断，不足以证明能处理真实草稿里模糊或缺上下文的代码。其余对照同样是局部能力检查，不能据此追认旧失败或发布 E。
