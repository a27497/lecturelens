## 已实现

- 复核显式区分：答案满足自身评分规则、答案缺少必需评分点、评分规则自相矛盾。答案与评分规则同时答错时，仍须另对课程证据检查；结构化返回不能保证模型正确区分这些情况。
- 练习草稿的每条拒绝必须定位字段、问题代码、纠正意见及 2–3 条原文引用。内容问题须引用该字段自己的课程证据；评分问题须同时引用标准答案与评分规则。程序拒绝伪造、超出送入上下文范围、引用了其他字段独有证据或缺少必要依据的意见。
- 当模型明确报告规则矛盾时，交给决策模型的反馈由本地规则要求重写冲突的评分条款，不能只补长参考答案。具体冲突文本仍在私有 `grounds` 中；这段修订方向是程序生成，不能算作模型自行提出有效修订。
- `grounds` 与拒绝结果原子持久化、checkpoint 恢复后重用；Evidence 短编号先还原成规范 ID，下一次决策再按当前上下文映射，避免引用串位。公开事件不含答案、引用正文或修订意见。
- 最终输出为两项 `rubric_checks` 加最多两条主要 `findings`，每字段至多一条。保持 300 输出 tokens、无额外模型调用或重试；Run 预算、取消、版本检查、最多两份候选与恢复边界不变。证据不足候选仍采用原有独立 `issues` 契约，本轮引文校验针对练习草稿。

实现位于 [quality.py](../../agent-service/src/lecturelens_agent/study/quality.py)、[provider.py](../../agent-service/src/lecturelens_agent/study/provider.py)、[runtime.py](../../agent-service/src/lecturelens_agent/study/runtime.py) 和 [context.py](../../agent-service/src/lecturelens_agent/study/context.py)。这一步服务于既有“学习目标 → 模型检索/提交候选 → 复核观察 → 修订或补查 → 持久化产物/明确失败”流程，没有新增自动评分或记忆功能。

## 最终 J 的具体结果

开发集的四份正确草稿全部接受；原评分矛盾 rp-04 被定位到第一题的答案和完整冲突规则，原无据单例断言 rp-06 被定位到解释及其引用片段。错误拒答 rp-08 仍正确拒绝。

rp-02 **仍失败**：模型指出应有两行输出，且引用了支持内部打印的课程原文；但同时返回 `answer_fails`，没有提供该分类要求的评分规则原文。原草稿的答案其实满足其自身错误规则，错的是二者与课程不符。验证器因此返回 `MODEL_REVIEW_CONTRACT`，没有将这条意见送入修订循环。本轮没有通过放宽契约或重计失败来提高分数。

新草稿的四份正确候选同样全部接受；rh-04 成功指出标准答案遗漏题目及规则明确要求的类型，rh-06 指出漏掉函数内部打印。逐项错误为：

- **rh-02 漏检**：第二题规则同时说两行答案得分，又说写两行一律零分，模型仍返回接受。这说明旧例被修好并不代表评分矛盾检测已泛化。
- **rh-08 协议失败**：模型定位了无据的布尔值内存表示断言，但把原片段中的小写 `it'll` 改成句首 `It'll`，与原文不完全匹配。精确引文校验拦截该意见，没有追认成正确拒绝。
- rh-06 的最终纠正内容有课程支持，但原始 `rubric_checks` 仍错误标作 `answer_fails`；由于它同时提交了答案、规则与课程引文，结构校验通过。这是语义局限，不能将“通过引文校验”解释成每个复核字段都正确。

程序只校验引文存在、字段和引用范围；**不证明引文在语义上支持纠正意见，也不证明引文之外没有支持材料**。本次 Codex 对照完整已提供片段检查最终意见，并非盲评或人工金标。复核成功的结果没有实际进入生成模型，因此本轮未证明有效 Agent 修订。

脚本默认仍拒绝保留题。显式 `--split holdout` 要求题集绑定当前冻结源码摘要，拒绝与开发集重复的 ID/完全相同草稿；此检查不能自动识别语义近似，报告不声称其能做到。所有标签、分组与预期理由都不发送给模型。

私有原始记录、源码与安全运行配置仍位于 Git 忽略目录 `.data/reviewer-probe/`；公开报告只保留统计、问题结论及冻结身份。未创建 Session、运行 LangGraph 真实模型流程或写入现有用户配置，未重启/部署服务。
