## 能力与执行边界

学习者先提出课程问题，再在同一 Session 追问指代对象、具体步骤或来源后文。模型选择搜索、读取相邻 Evidence 或生成独立解释；工具返回的证据、覆盖观察及复核意见影响下一步。服务端保存原始问题、解析后的目标、解释、来源、工具记录和有来源的事实；事实复用受 owner/course/revision/session 和 Evidence 内容校验约束。

取消、权限或版本变化、课程删除、预算或时间耗尽、协议错误及两份候选仍未通过均停止。每 Run 保持最多 6 次模型、8 次逻辑工具、64,000 保守 token 预留和 90 秒，不扩大预算来通过验收。事实账本是有范围约束的上下文复用，不是长期学习记忆。

## 执行机制验证

- 验证前保存当前源码、测试与边界代码的快照、文件哈希和原始工作区差异；修复后重新计算候选身份，初始快照不能冒充最终冻结。
- Python 全量回归使用本轮新建的独立 PostgreSQL/pgvector 测试数据库，不消费或清理已有测试库中的运行记录。数据库用例跳过不计为完整通过。
- 运行 Ruff lint、格式检查和 Java 的 Study 网关、Evidence Authority、Dense 检索及命中窗口回归。
- 失败日志与后续修复分别保留；确定性 Provider 只验证执行协议，不用于声称真实多轮语义质量通过。

## 真实模型质量协议

先完成开发回归，再冻结 Python 源码、Java 构建身份、模型与配置、工具协议和预算。冻结后才选择并编写全新保留课程和任务；开始正式运行后不得调整候选或任务。若失败后修改候选，原保留材料转为已消费开发材料，后继候选另建新保留集。

保留范围为两门未用于此前开发、诊断、演示或验收的公开课程，每门四段三轮对话，共八段对话、24 个目标，其中 20 个课程支持目标、4 个证据不足目标。选课时核对历次公开及私有来源清单；同一旧视频重新裁剪不计为未见课程。任务覆盖第二种方法的指代、具体条件或步骤、原引用后文、纠正先前表述及课程外追问；逐轮预先记录预期对象、必要条件、来源跨度和停止类型。选课与任务尚未完成，不将计划数字计为评测结果。

预定门槛：正确类型且在原 deadline 内完成至少 22/24；课程支持任务完整语义至少 18/20；四个证据不足任务全部正确停止；八段对话的指代和目标条件均保持正确；没有严重无据断言或跨 scope 来源复用。解释正确、目标完整、每条实质断言有对应来源支持须同时满足，引用 ID 存在不代替语义检查。复核由 AI 来源核查，单列人工复审缺口；机制测试和模型质量分别报告。

每次正式尝试在 START 前入账，保留失败、传输错误、原始输出、私有答案及 Trace，不用重试覆盖。报告包括各轮结果、是否复用事实、真实工具路径、复核拒绝与修订、模型/工具调用、实际 usage、延迟和停止原因。模型声称正确及 Run succeeded 都不直接等于语义通过。

使用隔离认证网关和专用评测账号，沿用 Java 的课程上传、准备与 Evidence 权威链路；正式模型运行与重型回归分开。原始调用、凭据、媒体和私有验收记录仅保存在 Git 忽略目录。完成后另验刷新、重启、取消、版本失效与删除，并记录清理和回滚结果。
